# 收音与输入能力矩阵

把「设备 × 能力」「输入源 × 行为」「搭配错位时会看到什么」集中在一页，
排查配置问题先查这里（对标 SayAll《遥控器与输入工具能力矩阵》，按 Linux
本机直贴链路改写：本项目不经过第三方输入法，语音键语义是"按住收音、
松开交识别"，因此没有 Mac 版那种长按/点按错配；矩阵保留两处真实的错位面：
**设备收音方式**与**多源抢占**）。

## 1. 设备能力矩阵

| 设备 | 语音（ATVV） | 按键 | Profile | 备注 |
| --- | --- | --- | --- | --- |
| 小米遥控器 2 Pro（RC003-MS） | ✅ 按住收音 | ✅ 全键 | `rc003` | 主力机型；语音键默认映射 F24 |
| 小米遥控器 2（RC001-MS） | ✅ 按住收音 | ✅ 全键 | `rc003` | 与 RC003 同 profile |
| 小米/米家语音遥控器（ARN9） | ✅ 按住收音 | ✅ 全键 | `rc003` | 键码与 RC003 一致；键位图鉴有独立外形 |
| 其他 ATVV 遥控器（Google/Fire TV 等） | ✅ 按住收音 | 视 evdev 而定 | `generic-atvv` | 在「设备」页手动指定 Generic |
| Apple Siri Remote 1 代 | ❌ | ✅ | `apple-siri-remote-1` | 无 ATVV，语音不可用 |
| 手机浏览器（虚拟输入源） | ✅ 按住收音 | ✅ 方向/确认/音量 | 内置 | 需开 `phone` 段并完成配对 |

统一语义：**语音键按住即录、松开即交识别**；单次上限为 `max_utterance_seconds`
（手机可用 `phone.max_utterance_seconds` 单独设）。到达上限会截断并标注
「已截断」（DOM-09），字幕与历史都带同一标记。

## 2. 输入源行为矩阵

| 行为 | 遥控器（BLE） | 手机（浏览器） |
| --- | --- | --- |
| 收音触发 | 按住语音键 | 按住「说话」按钮 |
| 抢占优先级 | **高**：随时抢占麦克风 | 低：被抢占时收到 `preempted`，半句仍送识别 |
| 断线时的半句 | 仍送识别（不丢字） | 仍送识别（不丢字） |
| 按键注入 | root helper（evdev→uinput） | helper 白名单键（导航/音量/电源） |
| 重复/长按 | 内核 `value=2` → 重按/宏重执行 | 页面侧 500ms 后连发 |
| 身份标注 | `remote` + 设备名 | `phone` + 配对名 |

多源规则（I1）：**同一时刻只有一路音频**。遥控器按下即 `AcquireAudioForce`
抢占；被抢占方立刻停采并收到通知，已说的话照常进链路。手机之间互斥，先到先得。

## 3. 错位与症状表

| 症状 | 常见原因 | 处理 |
| --- | --- | --- |
| 按住语音键没反应 | 语音键映射被改 / 设备断连 | 「按键映射」检查语音键；概览页看连接状态 |
| 说话很长但只出半句 | 触发单次上限截断 | 上限见「已截断」标注；调大 `max_utterance_seconds` |
| 手机说一半突然停、提示被抢 | 遥控器按了语音键 | 预期行为；后说的排队识别 |
| 手机「聆听」一直亮但不出字 | 手机被抢占未收到通知（异常） | 断开重连手机；看服务日志 |
| 长按方向键只走一格 | 映射到宏/动作而非原生键 | 「按键映射」把该键设为原生/方向键 |
| 字幕显示的是地址不是名字 | 旧版本历史数据 | 新数据带 `source_name`；历史行优先显示名字 |
| 按键次数不涨 | remap 服务未运行 | `sudo make install-remap`；看 `systemctl status xiaomi-remote-remap` |

## 4. 与 SayAll（Mac/Windows）口径的差异

- **不改系统默认输入/输出设备**：本项目用 PipeWire 虚拟麦克风桥接 ASR，
  粘贴走 X11/Wayland，不经第三方输入法；因此没有「语音工具触发键对齐」问题。
- **收音方式只有一种**（按住），Mac 版的「模拟 Fn 点按 / Typeless 兼容」不适用。
- **隐私口径一致**：语音只在内存过一遍，不落盘不上传；历史/统计在本机；
  Agent（MCP）访问只读、可撤销、审计只记次数。
