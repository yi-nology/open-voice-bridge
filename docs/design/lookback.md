# 回眸（可选录音）设计稿 — S8

- 状态：已定稿并实施（2026-11-14）
- 性质：隐私敏感功能；本稿是动手前的设计闸门
- 关联：`docs/design/evolution-roadmap.md` S8、`SECURITY.md`、SEC-02（音频不进日志）

## 1. 解决什么

漏抓是真实痛点：没按住语音键就说了、松手太早、识别失败、说话时焦点刚好丢了——
话音就此消失。「回眸」让用户把**刚说过的那几十秒**捞回来听写一遍，像给声音一个撤销键。

## 2. 形态

- 桌面麦克风音频的**内存滚动环**（默认 30 秒，可调 5–60 秒），环满即最旧的自动出环。
- 与唤醒词共用一条桌面麦采集会话（`internal/miccap`）：二者都关时根本不打开麦克风。
- 触发方式只有一个：字幕页「识别刚才 N 秒」按钮。**绝不自动识别、绝不自动上屏。**
- 触发后环内音频走共享转写链，听写结果进焦点窗口与历史，来源标 `lookback`（回眸）。

## 3. 隐私模型（不可妥协项）

1. **只在内存**——音频字节永不落盘、永不写日志（SEC-02 口径同样适用于环）。
2. **默认关闭**——不开启就没有任何缓冲，麦克风也不开。
3. **有界滚动**——只留最近 N 秒，旧音频被覆盖即消失，无副本。
4. **关即忘记**——关闭开关、服务退出、进程崩溃（内存）即清空；关闭动作显式清环。
5. **显式动作才识别**——环只是"记着"，只有用户按下按钮才进入识别链路。
6. **来源透明**——历史与字幕都标「回眸」，用户随时能分辨哪些话是捞回来的。
7. 与唤醒词一致的公开声明：识别走 ASR 链路；配本地引擎才完全离线。

## 4. 非目标（v1 明确不做）

- 不提供音频导出/回放（真要给，必须另立设计稿并加二次确认）。
- 不做磁盘录音、不做云端上传、不做跨设备同步。
- 不做语音活动预过滤以外的任何音频分析（不做人声分离、不做身份识别）。

## 5. 实现要点

- `internal/agent/lookback.go`：有界环（加锁、覆盖即弃）+ `LookbackCapture(n)` 拷贝尾段。
- 桌面麦单会话复用：唤醒监听与回眸共享帧流；`SetWake`/`SetLookback` 共同决定会话存续。
- 听写沿用 `SpeechPipeline.Transcribe`，`SourceRef{Kind:"lookback", Name:"回眸"}`。
- 配置：`lookback_enabled`、`lookback_seconds`（5..60，默认 30），UI 在字幕页，热生效。
- 真机项：采集工具可用性、环内存占用实测（30 秒 ≈ 960 KB/环，可接受）。
