  - **历史 ID 由扇出预铸，store 的唯一性守卫形同虚设**（④）：扇出用 `transcript.At` 自己拼 ID，于是 `Append` 的 `if entry.ID == ""` 分支对它**唯一的生产写者**永不执行，DOM-14 的同刻去重守卫（`internal/history/history.go:85-96`）覆盖不到任何人；两条同一时间戳的转写共用一个 ID，`Delete` 会把带这个 ID 的行全删掉——删一条带走两条。**口径必须说清：这是潜在缺陷不是现网故障**。唯一生产者是 `internal/agent/pipeline.go:141` 的 `At: time.Now()`（纳秒分辨率），且所有提前返回都是 `Transcript{}, false`，所以今天撞不上；可达的部分是那份**重复的格式串**（R5 违规），任何将来复用时间戳的生产者（回放、导入、客户端自带时钟）都会静默踩中。修法是把 ID 留空让 store 成为唯一出处，不是给扇出换个更好的格式串。失败测试驱动真 store、两条转写共用一个 `At`，实测 `two transcripts share id "20261112-093200.000000000"`，修后两条可独立删除。前端把 `entry.id` 当不透明删除令牌用（`web/ui.html:2713` 的 `deleteHistory(id)` 原样回传，不解析格式），改 ID 出处零兼容代价。
